静态博客：源码与发布分开维护 ​

静态网站可以由私有源码构建，再把经过审核的 HTML、CSS 和 JavaScript 发布给读者。网站公开与源码公开是两个独立决定。

一个具体例子 ​

本博客用 VitePress 组织 Markdown 页面。源码在开发仓库维护，构建后的站点文件放入账号站点的 blog/ 目录，读者通过 /blog/ 访问。个人主页在根目录，两者各自构建。

内容用途是否发布
审核过的文章和项目介绍提供读者可阅读的知识是
HTML、样式和浏览器脚本展示页面与本地搜索是
简历、个人原始资料、环境配置私人维护和开发否
仓库历史、依赖目录与缓存开发与构建否

浏览器脚本本身会公开，不能把密钥写入前端，再以“源码仓库私有”为理由认为它安全。

路径与链接 ​

部署到子路径时，构建的 base 必须与目录一致。例如本博客采用 /blog/，资源和内部页面链接也需要匹配该前缀。不能只复制一个首页，而漏掉文章页、资源与搜索数据。

站内链接用于连续阅读；其他网站在新标签页打开，保留当前阅读位置。更换正式地址时更新公开入口，不依赖旧模板网站自动跳转。

发布前检查 ​

先确定允许公开的页面，再构建、检查产物和链接。排除敏感页面也要检查搜索数据，避免正文没显示但仍能搜索到私人材料。页面可访问只说明发布成功，不能代替功能验收或完整安全审计。

VitePress 的路径和排除选项见 官方站点配置，链接行为见 官方路由说明。本例核对于 2026-10-13。
